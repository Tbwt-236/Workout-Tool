# Feature Specification: 训练记录最小闭环

**Feature Branch**: `main`

**Created**: 2026-08-03

**Status**: Approved — product-owner approval recorded 2026-08-04

**2026-09-13 amendment**: 用户明确要求中/英两版及精简界面文字；新增 FR-019，并将 FR-007、SC-006 的中文限定调整为当前界面语言。前端多轮确认要求不变。

**Input**: User description: "按照当前产品计划继续推进，先交付创建训练、记录至少一组、完成训练并在历史中看到记录的最小移动端闭环。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 完成并保存一场训练 (Priority: P1)

作为一名刚开始力量训练的用户，我希望无需注册账号就能快速开始一场训练，记录动作、次数和可选重量，完成后立即看到保存结果，从而确认今天的训练没有丢失。

**Why this priority**: 这是产品的最小价值闭环，也是后续模板、趋势、任务和游戏化反馈可信的数据来源。

**Independent Test**: 在没有任何既有数据和网络连接的设备上，用户可以开始训练，新增一个动作和一组有效记录，完成训练，并看到本次训练摘要。

**Acceptance Scenarios**:

1. **Given** 当前没有进行中的训练，**When** 用户选择开始训练，**Then** 系统创建一场进行中的训练，并允许用户添加动作。
2. **Given** 用户已添加动作，**When** 用户输入有效次数和可选重量并保存，**Then** 当前训练立即显示该组的完整记录。
3. **Given** 当前训练至少包含一个动作和一组有效记录，**When** 用户确认完成训练，**Then** 系统保存完成时间、训练内容和汇总信息，并显示完成结果。
4. **Given** 当前训练没有有效组，**When** 用户尝试完成，**Then** 系统不生成历史记录，并明确说明至少需要一组有效记录。
5. **Given** 用户处于无网络环境，**When** 用户完成上述流程，**Then** 所有核心操作仍然可用且结果一致。
6. **Given** 用户已输入内容或已有有效训练组，**When** 在简体中文与英文之间切换，**Then** 按钮、字段、计数、确认和错误提示使用所选语言，输入、训练数据和当前操作状态保持不变；自填动作名称不翻译。该要求同样适用于摘要、历史与纠错界面。

---

### User Story 2 - 查看和管理训练历史 (Priority: P2)

作为完成过训练的用户，我希望通过日历查看哪些日期练过，点击查看当天训练和每次训练的详细内容，并能删除错误记录，从而回顾真实训练且保有对本地数据的控制。

**Why this priority**: 历史记录让一次性录入转化为可回顾的数据资产，也是验证“已保存”的直接证据。

**Independent Test**: 使用跨月和同日多场的完成记录夹具，用户可以通过月历选择日期，查看当天按完成时间倒序的记录、打开详情、确认数据与原记录一致，并在二次确认后只删除指定记录。

**Acceptance Scenarios**:

1. **Given** 存在多条已完成训练，**When** 用户打开历史并选择一个日期，**Then** 月历标出有训练的日期，所选日期的记录按完成时间从新到旧展示日期、时长、动作数和组数，并提供详情路径。
2. **Given** 用户打开一条历史记录，**When** 用户查看详情，**Then** 系统显示该次训练的每个动作及其组次、次数和可选重量。
3. **Given** 用户请求删除一条历史记录，**When** 用户尚未二次确认，**Then** 系统保留该记录且不更改其他数据。
4. **Given** 用户确认删除一条历史记录，**When** 删除完成，**Then** 该记录不再出现在列表和详情中，其他记录保持不变。
5. **Given** 用户已经完成并保存训练，**When** 用户关闭并重新打开产品，**Then** 完成记录仍可在历史中查看且数据一致。
6. **Given** 用户切换月份或选择无完成记录的日期，**When** 查看该月和该日，**Then** 标记与已保存记录一致，无记录日显示空状态，不创建或改写训练；从详情返回可继续浏览先前月份和日期。

### User Story 3 - 在完成前纠正记录错误 (Priority: P3)

作为正在训练的用户，我希望在完成训练前修正动作名称、修改或删除误填的组，并能安全取消整场训练，从而避免错误数据污染历史。

**Why this priority**: 健身房场景容易输错重量或次数；最低限度的纠错能力能保证训练数据可信。

**Independent Test**: 在一场包含两组记录的进行中训练里，用户可以修正动作名称、修改其中一组、删除另一组，并在取消整场训练时通过确认避免误操作。

**Acceptance Scenarios**:

1. **Given** 当前训练已有动作和一组记录，**When** 用户修正动作名称或将该组修改为另一组有效数据，**Then** 当前训练仅显示修改后的值且汇总同步更新。
2. **Given** 当前训练已有多组记录，**When** 用户删除其中一组，**Then** 仅目标组被移除且汇总同步更新。
3. **Given** 当前训练包含未完成内容，**When** 用户请求取消训练但未确认，**Then** 进行中内容保持不变。
4. **Given** 当前训练包含未完成内容，**When** 用户确认取消，**Then** 系统结束该进行中训练且不生成完成历史。

### Edge Cases

- 当用户连续触发“开始训练”时，系统不得创建多个同时进行的训练。
- 动作名称只有空格、次数为零或负数、次数含小数、重量为负数或超出允许范围时，该组不得保存。
- 删除当前训练中唯一有效组后，用户不得完成训练，直到再次保存有效组。
- 用户取消删除历史记录时，原记录和排序必须保持不变。
- 没有完成记录时，历史页面必须说明当前为空，并提供开始第一场训练的路径。
- 数据读取或保存失败时，系统必须明确提示未成功，不能显示虚假的完成状态。
- 设备时间发生变化时，已经保存的记录内容不得被改写；列表继续依据记录中的完成时间排序。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 用户必须能够在不注册账号、不登录和无网络连接的情况下开始训练。
- **FR-002**: 系统同时最多只能存在一场进行中的训练；重复开始操作必须回到现有训练或被明确阻止。
- **FR-003**: 进行中的训练必须记录开始时间，并在用户完成时记录完成时间和由两者计算的训练时长。
- **FR-004**: 用户必须能够为进行中的训练添加一个或多个以名称标识的动作；去除首尾空格后的动作名称必须为 1–80 个字符。
- **FR-005**: 用户必须能够为动作添加一组或多组记录，每组包含 1–999 的整数次数以及可选的公斤重量。
- **FR-006**: 当用户填写重量时，系统只接受大于 0 且不超过 1000 公斤、最多一位小数的数值；未填写重量表示该组不记录负重。
- **FR-007**: 系统必须在保存前验证动作名称、次数和重量，并针对无效字段给出当前界面语言的可执行提示。
- **FR-008**: 用户必须能够在完成训练前修改动作名称，以及修改或删除任意一组；训练内容和汇总必须立即反映最新有效记录。
- **FR-009**: 进行中的训练必须展示当前动作数和有效组数。
- **FR-010**: 系统必须阻止用户完成不包含有效组的训练，并说明完成条件。
- **FR-011**: 完成训练必须经过用户明确确认；成功后系统必须生成且仅生成一条不可继续编辑的完成记录。
- **FR-012**: 完成结果必须展示训练日期、时长、动作数和有效组数，并提供进入训练历史的路径。
- **FR-013**: 历史首屏必须以月历展示，并标记有完成训练的日期；用户能够切换月份、选择日期，查看当天按完成时间从新到旧排列的训练日期、时长、动作数和有效组数，再进入详情。同日多场必须均可访问，无记录日期显示可理解的空状态；整个历史为空时提供开始训练入口。日历按设备当前本地日期展示，不改写已保存的UTC完成时间。（2026-09-16依据用户明确日历偏好修订；具体点击表现继续共创。）
- **FR-014**: 用户必须能够查看完成记录的每个动作以及各组的次数和可选重量；显示值必须与保存时一致。
- **FR-015**: 完成记录必须在产品关闭并重新打开后仍然存在，且核心记录流程不得依赖网络连接。
- **FR-016**: 用户必须能够请求删除一条完成记录；删除必须二次确认，并且只能影响用户指定的记录。
- **FR-017**: 用户必须能够取消进行中的训练；包含已输入内容时必须二次确认，取消后不得生成完成历史。
- **FR-018**: 保存、读取或删除失败时，系统必须明确告知用户操作未完成，并保留可以安全重试的状态。
- **FR-019**: 全部核心界面必须支持简体中文与英文，默认简体中文并允许切换。两种语言共用同一份训练数据；切换不得丢失输入、修改数据或触发业务操作。常用按钮采用简短动词（如“记录 / Log”“完成 / Finish”），必要单位、完成/删除/取消确认及错误修正信息必须清晰；自填动作名称原样保留，重量统一为 kg。

### Key Entities *(include if feature involves data)*

- **Workout Session（训练会话）**: 一场进行中或已完成的训练；包含唯一标识、状态、开始时间、可选完成时间、动作列表和汇总。进行中会话不得出现在完成历史中。
- **Exercise Entry（动作记录）**: 训练会话内按顺序排列的一个动作；包含动作名称和一组或多组训练组。
- **Set Entry（训练组）**: 某个动作的一次有效记录；包含组序、次数和可选公斤重量。

## Scope Boundaries

### Included

- 单一设备、单一匿名使用者的本地训练记录。
- 手动标识动作并记录组数、次数和可选重量。
- 完成摘要、历史列表、历史详情和单条记录删除。
- 进行中数据的编辑、组删除和整场取消。

### Intentionally Deferred

- 账号、登录、云同步、跨设备恢复和多人数据。
- 训练模板、动作教学库、推荐计划和新手目标设置。
- 休息计时、个人最佳、趋势图和训练量分析。
- 异常退出后的未完成训练恢复；在后续可靠性切片中定义。
- XP、等级、连续训练、任务、勋章和其他游戏化反馈。
- AI 建议、订阅、支付、推送、健康平台同步和公开社交。
- 全量数据导出和账户级数据删除；MVP 隐私切片将另行定义。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 5 位目标用户中至少 4 位无需口头指导，即可首次完成“开始训练—记录一组—完成—打开历史详情”的完整任务。
- **SC-002**: 5 位目标用户中至少 4 位能在打开产品后 10 秒内进入可记录第一组的进行中训练状态。
- **SC-003**: 在不包含真实运动等待时间的可用性测试中，完整主流程的中位完成时间不超过 2 分钟。
- **SC-004**: 连续执行 20 次完成、重新打开和查看历史的验证流程时，所有已保存动作、次数和重量均与输入一致，且不产生重复完成记录。
- **SC-005**: 飞行模式下，开始、记录、完成、重新打开查看以及删除一条历史记录的测试流程全部成功。
- **SC-006**: 在简体中文和英文下分别执行空动作名、非法次数和非法重量的边界测试，100% 的无效输入被阻止，并显示当前界面语言的对应字段修正提示。
- **SC-007**: 取消进行中训练或取消删除历史的验证流程中，100% 不产生意外完成记录或数据删除。

## Assumptions

- 第一条切片服务于单一设备上的匿名用户，不需要账户体系或联网服务。
- 中国大陆为首发目标市场，界面默认简体中文并支持英文切换；两种语言属于同一应用，重量统一使用公斤。双语要求不改变平台和首发市场决策。
- 本切片允许用户用名称标识动作，不在此阶段定义完整动作库或动作教学内容。
- 历史记录在本切片中完成后只读；用户可以整条删除，但不能修改已完成训练。
- 可用性验证可以使用测试训练数据完成，不要求参与者实际完成一场完整力量训练。
- 访谈招募与参与者联络由产品负责人负责；匿名研究证据仍用于后续调整规格和 MVP 边界。
- 未完成训练的异常退出恢复有明确价值，但根据当前路线图推迟到后续训练可靠性切片。
