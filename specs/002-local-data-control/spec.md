# Feature Specification: 本地数据说明与最小 JSON 导出

**Created**: 2026-10-02 | **Updated**: 2026-10-12

**Status**: Approved for implementation / 已实现，原生与用户验收未完成。目录标识 `002-local-data-control`，不修改活动 feature 或 001 任务状态。

## 批准依据与当前范围

三轮直接答复依次为：历史页右上角「数据」（空历史也能找到）；“第二版”（底部面板）；针对“全部已完成训练导出为 JSON、空历史导出置灰、系统选择结束后留在面板”的可点交互提案答复 **“可以的”**。由此开始真实 App 实施，不再重复询问这些选择。完整记录见[前端共创](../../docs/design/FRONTEND_REVIEW.md)。

本规格替代10-02草案及10-12早期未决文字：空历史不能发起用户导出；不新增独立路由；不保留不能证明接收方读完的持久交接清单。缓存24小时资格阈值是依据[研究](research.md)采用的工程选择，并非用户逐字指定或平台安全保证。具体原生体验仍需在设备核验。

沿用 B 亮橙/蓝黑/雾白、简短中英标签、训练/历史双导航。无账号、云、AI、付费、导入恢复、全量删除、后台上传、入站分享或遥测。001 T029/T030/T031/T033不因本功能代码完成而关闭；当前验证只用合成数据。

## User Scenarios & Testing

### US1 随时理解数据用途（P1）

空历史、有历史或训练进行中均可从历史右上角打开面板，查看字段、用途、本地存储、既有单条删除、导出及副本限制。切语言、展开说明或关闭不清空草稿、原始输入、日历月份/选日；不替用户保存训练，不记录“已接受”，不改变001记录流程。

### US2 主动取出全部已完成训练（P2）

1. 面板说明全部已完成历史与明文范围；点击短按钮「导出 / Export」后完整生成文件，直接进入系统选择，不增加第二次分享确认。
2. 保留开始/完成UTC时间、时长、名称、动作/组顺序、次数、十分之一公斤整数重量；null保留原义。
3. 空历史显示0场并禁用导出；仓储仍可返回真实空快照，服务拒绝生成空历史文件。读取失败不能伪装为0场。
4. 导出对应一个一致快照，坏记录导致全量失败，不静默跳过；当前草稿、原始输入、内部ID及诊断不进入文件。
5. 系统选择结束后仍留面板，可关闭回历史；返回只说明本次调用结束，不显示“已保存/已送达”。

### US3 关闭、中断与失败可恢复（P3）

交接前关闭或退后台撤销继续分享意图，不能中止的读取/写入完成后只收尾，不迟弹系统界面。任务同步防重，锁保留到资源收尾完成。开始调用系统后保守保留文件，返回不自动再次分享。进程重启不会恢复自动分享；可重新显式导出。故障不修改训练；文案可重试且不泄露内部异常。

## Functional Requirements

- **FR-001**：中英数据说明涵盖字段、记录/回顾用途、本地存储、单条删除、明文导出及系统备份/接收方边界，不要求账号。
- **FR-002**：记录实际数据流及同意审查边界；不把关闭说明视为法律同意，也不从本实现推出法律合规或真实数据试用批准。001 T030继续开放。
- **FR-003**：不新增选择表、训练门禁、撤回清稿或训练schema迁移，保持001开始/编辑/完成语义。
- **FR-004**：历史右上角数据入口打开底部面板；不加第三tab或独立路由；空历史说明可达。
- **FR-005**：仅用户主动发起，全部已完成历史、明文范围预先可见；不含草稿、原始输入、内部标识或阅读轨迹。
- **FR-006**：UTF-8 JSON v1，含格式、版本、生成时间、快照时点和明确重量单位；无需联网或付费。
- **FR-007**：保持UTC、时长、原名称、位置、次数、重量和null，不翻译用户内容。
- **FR-008**：共享现有连接所有者，一次SQL一致读取并重验全部聚合；保存/删除互斥；编码/文件/分享前释放仓储锁。
- **FR-009**：空历史禁用导出；失败显式反馈，不降级为空集合。
- **FR-010**：只有完整文件及仍有效请求可直接进入系统选择，不预设接收人或自动发送。
- **FR-011**：单活动任务，重复返回Busy；收尾后释放对应锁，不允许旧结果开第二次分享。
- **FR-012**：交接前关闭/后台取消继续分享；交接后不假装撤回；重启只恢复机会性清理，不自动分享。
- **FR-013**：显示准备、错误和重试；系统void返回后恢复可操作面板，不推断保存、取消或接收方读取结束。
- **FR-014**：专属缓存目录、严格名称、唯一文件、先partial后完整提交；活动文件受保护，适配器拒绝目录外或非活动分享/释放。
- **FR-015**：未交接文件在取消/失败时尝试移除；已开始交接的完整文件不立即删。下次启动或导出尝试清理修改时间至少24小时前的受控非活动文件；跳过未知名称、目录、未来/无效时间，失败以后重试。系统可提前清缓存，实际残留可更久，接收方迟读可能需要重新导出；无安全擦除、读完证明或后台准时清理承诺。
- **FR-016**：故障使用当前语言稳定文案，不输出SQL、路径、训练正文或堆栈；不新增追踪。原生SDK自身无法恢复的失败须诚实披露。
- **FR-017**：触控、滚动、读屏及中英小屏设备验收单列；切语言/关闭/导出/返回保持训练输入及日历位置。

## Success Criteria

| 标准 | 验收要求 |
| --- | --- |
| SC-001 | 空/有历史、进行中训练均可达；关闭/切语言/取消/失败中原训练及输入保持 |
| SC-002 | 1000场/4000动作/20000组逐字段一致；空快照不启动分享；无额外草稿 |
| SC-003 | 20轮保存/删除交错，每份文件对应单一快照；分享不占数据库锁 |
| SC-004 | 重复、关闭、前后台、进程中断及故障无重复分享、错误清理、锁泄漏或虚假送达；自动测试和原生证据分开 |
| SC-005 | 5名目标用户至少4名30秒内找到入口并解释副本去向，仅合成数据 |
| SC-006 | 中英、320宽、键盘和读屏完成说明→导出→取消/返回，关键反馈可见 |

通过情况见[verification](verification.md)，不以已批准界面或桌面测试代替原生与真实用户验收。

## 本步学习验收

目标：一致快照、系统分享边界L2；范围和缓存取舍L3。练习解释“导出后删App内记录不能撤回外部文件”，并区分文件生成、系统返回与实际保存。可汇报：“三轮共创已确认，真实App接入JSON导出，原生和真实用户验收继续推进。”未达标时沿US1–US3复述；规格/实现完成与本人掌握分开记录。
