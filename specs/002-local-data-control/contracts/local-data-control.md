**Spec**: [../spec.md](../spec.md) | **Model**: [../data-model.md](../data-model.md)

## 1. UI and Review Boundary

A 历史页轻入口、B 详情进入独立说明页均待用户答复，后续低保真和可点击确认继续。两者共用说明与全部历史导出，不加第三 tab；空历史仍可达。

说明列明字段、目的、本地存储、单条删除、明文导出、接收方和待核系统备份。候选按钮为“数据 / Data”“数据说明 / Data info”“导出全部训练 / Export workouts”“返回 / Back”。入口附近须清楚写明全部已完成历史和明文文件范围。

本切片不新增用户选择持久化、记录门禁或撤回清稿。打开/关闭说明不表示法律同意，也不改变 001 流程。实施/真实试用前审查数据流及同意问题；额外用户同意机制是否必要由研究与独立批准决定，不从本契约推出法律结论。001 T030 保持原条件。

## 2. Snapshot and Encoding

### `readExportSnapshot()`

- 与既有仓储共享连接所有者及互斥；并发写入时返回 Busy 供重试，不返回假空数据。
- 一个一致性读事务读取全部聚合并重验证；任何故障或损坏整体失败。
- 返回前释放数据库事务/锁。编码、文件、系统分享不得继续占用数据库事务。
- 空历史为 workouts 空数组；不写回训练，不包含草稿或原始输入。

### `encodeExport(snapshot, exportedAt)`

- 只编码 data-model 的 v1 字段白名单；保留顺序、UTC、单位、null 与用户原文。
- 输出标准 UTF-8 JSON；无 SQL、路径、内部 ID/localKey、阅读轨迹或日志。
- 拒绝无效值，不静默省略损坏记录，也不依靠 JSON 的 NaN/undefined 转换。

## 3. One Explicit Export Request

### `requestExport()`

1. 用户在范围说明旁主动点击“导出全部训练”，才分配 taskId 和同步获取活动任务锁；无该请求不读数据、不建文件、不分享。
2. 获取快照 → 释放仓储锁 → 编码 → 先持久化文件归属 → 写 partial → 完整关闭/校验/提交文件。
3. 文件完整后持久化 handoffPending。再次检查所属页面和本次请求仍有效、App 仍在前台，才直接打开系统保存/分享选择；不增加等待第二次点击的 ready 页面。
4. 用户在系统中自行选择接收方；不预设联系人，不自动发送，不为分享不可用增加网络备用路径。
5. 全程不改训练、草稿、原始输入、语言或日历位置。完成后的新请求总是重新取快照，不默默重发旧文件。

“文件已生成”只说明本地步骤完成；系统打开、取消或结果未知须使用各自可证反馈，不承诺接收方已保存。

## 4. Cancellation, Ownership and Lock Release

| 情况 | 最小行为 |
| --- | --- |
| 正在生成时再次点击 | Busy，不生成第二份活动任务 |
| 交接前离开所属页面/进入后台 | 同步撤销本次交接意图；可中止操作则中止，不可中止 IO 的迟到结果只收尾清理，不打开系统界面 |
| 文件生成后、交接前请求已失效 | 不交接，按未交接文件清理，结束本任务 |
| 已调用系统后页面卸载/后台 | 不假装撤回系统操作；保持文件保护，不用后台事件作为取消或接收成功证据 |
| 平台明确取消或调用失败 | 如实反馈；释放本任务锁，文件按实际可清理状态处置 |
| 只能证明打开或返回，无法证明接收结果 | 保持结果未知；不宣称成功，也不重复打开 |
| 旧任务迟到结果 | 仅处理旧 taskId 的资源，不覆盖新状态、不释放新任务锁、不触发交接 |
| 进程终止后重启 | 活动内存锁从空状态开始；不自动继续生成/分享，只恢复残留文件核对与清理 |

Android SDK57候选expo-sharing的返回值为void，不能映射为“已取消”或“接收方已保存”。该平台的系统返回应归为结果未知；Cancelled只用于本应用交接前确实取消，或未来适配器具有可靠取消证据的情况。清理安全性不能从这个返回值推导。

锁释放不等于文件可删除。交接前任务在 IO 收尾后释放；交接后的释放点必须依据平台可证的流程返回/调用失败条件，由研究和设备测试确定。不能用任意超时绕过单一系统界面限制。当前不预设平台 Promise resolve 就表示已送达或文件已停止读取。

文件/分享端口只接受当前任务拥有的受控句柄；任意路径、失效请求和旧 taskId 均不能发起分享。回前台只更新状态/清理，不自动再次调用分享。

## 5. File Recovery and Cleanup

### `cleanupExportFiles()`

- 只处理专属目录内可证明归属的文件。先持久化清单再创建数据文件，先持久化可能交接标记再调用系统。
- 清单写失败：不创建新数据文件；可能交接标记写失败：不调用系统。
- 启动/回前台对账清单和目录：缺失文件消除失效条目；已知未交接 partial/取消文件安全清理；孤儿完整文件或交接状态不明的文件进入隔离/待清理，不自动分享。
- 对无完整清单的残留，必须通过专属目录和严格命名规则证明属于本功能，才能恢复受控条目；归属或交接安全性不明不得猜测删除。
- 只接受受控相对路径，不跟随目录外链接；不删除训练库或用户保存的副本。
- 活动文件及系统可能仍使用的文件不提前删除。平台已证明结束的副本尽快清理；清理失败保留状态，后续启动/前台重试，不谎报已移除。
- 未知交接状态的 24 小时仅为候选清理资格阈值，平台未核。实际清理还需可证安全条件及应用执行机会；不承诺实际保留上限或后台准时删除。
- 设备时钟异常不能单独使文件变成“可安全清理”。若平台无法提供可解释、可测的安全条件，先修订并确认 Q2，不以无限保留替代研究。

中断测试至少覆盖：登记后/建文件前、写入中、提交完整文件后/清单阶段更新前、交接标记后/系统调用前、系统调用后/回调前、文件删除后/清单清除前。残留恢复与系统分享测试须分别提供桌面和原生证据。

## 6. Error and Status Contract

| 状态/错误 | 用户含义 | 恢复边界 |
| --- | --- | --- |
| Busy | 导出或数据库操作进行中，请稍后重试 | 无第二个任务 |
| SnapshotUnavailable / InvalidStoredData | 暂无法完整读取训练 | 不生成部分导出 |
| FileUnavailable | 无法生成导出文件 | 原训练不变；清理受控部分文件，可显式重试 |
| ShareUnavailable | 暂无法打开系统保存/分享 | 不自动联网备用，不显示送达 |
| Cancelled | 本次流程已取消，有明确取消依据 | 不改变训练；收尾后可发起新任务 |
| Opened / OutcomeUnknown | 有打开证据 / 无法确认接收结果 | 不显示接收方保存成功，不自动再分享 |
| CleanupPending / RecoveryPending | 临时副本仍待安全清理/核对 | 不宣称删除完成，不泄露路径或正文 |

文案使用当前语言；不直接展示或记录包含敏感内容的异常字符串。
