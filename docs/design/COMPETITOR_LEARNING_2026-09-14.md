# FitQuest 竞品学习与设计反馈

调研日期：2026-09-14。用途：为下一轮界面共创和开发优先级提供依据。

## 结论

建议以 Strong、Hevy 为录组交互的主要参考，以训记校准国内竞争，以 Fitbod 学习“减少训练决策”的价值，以 JEFIT、Keep 观察成熟产品的功能与商业边界。最值得优先验证的是：同一行填写重量/次数并确认一组，是否比当前独立输入表单更顺手。

“简洁、中英文、力量感”应作为体验要求，暂不能作为独有卖点。训记已经提供简体中文、繁体中文与英文；Keep 的当前商店介绍也包含健身房力量训练记录。FitQuest 需要验证更具体的价值，例如新手能否更快录入、改错和找回历史。[训记商店页](https://apps.apple.com/cn/app/%E8%AE%AD%E8%AE%B0-%E8%AE%AD%E7%BB%83%E8%AE%A1%E5%88%92%E4%B8%93%E5%AE%B6/id1464915553)、[Keep 商店页](https://apps.apple.com/cn/app/keep-ai-%E8%BF%90%E5%8A%A8%E6%95%99%E7%BB%83/id952694580?platform=ipad)

以上是基于公开资料的产品判断，不是已验证的市场差异或收入预测。

## 研究方法与边界

- 选取六款国内外有公开商店与持续产品资料、且与力量训练相关的代表性产品；按相似性选择，不称为市场份额排名。
- 核对官方功能说明、帮助中心、商店内购信息，摘取七条与当前流程直接相关的用户反馈作定性分析。评论不代表全体用户，商店选出的展示顺序也有偏差。
- 本轮未安装或付费试用这些 App。官方图片链接已找到，但浏览器访问未完成可视核对，因此本报告不宣称实际看过全部截图、测试过原生操作或量过点击耗时。
- Strong 部分帮助文章最后更新于 2021/2022 年，作为当前在线交互说明使用；最新版本、平台差异和键盘行为仍需实机复核。价格仅为下列渠道在本次检索显示的快照，不混用币种、地区或购买渠道。

## 对现有讨论稿的具体反馈

下表是我的设计判断，尚未获得用户批准，不改变现有规格或开发完成状态。

| 当前讨论稿 | 下一轮建议 | 原因与核对方式 |
| --- | --- | --- |
| 已录组列表和输入区分开 | 增加一版“组行内输入＋确认”与现稿比较 | 同一组的信息与操作靠近，可能减少视线移动；观察新用户能否识别待录和已录，不能预判一定更快。 |
| 改组先点铅笔，再去输入区 | 比较直接点数值进入编辑，保留可发现的编辑提示 | 减少寻找目标组和编辑位置的往返；需防误触和未提交修改丢失。 |
| 当前只用下拉切换动作 | 比较动作标题列表，当前动作展开、其他动作可收起 | 让整场训练内容更可见；多动作是否造成滚动负担需实测。 |
| “改名”独占组表下方一行 | 移到动作标题旁的更多菜单 | 名称属于动作层级；低频操作不持续占据录组区域。 |
| 品牌、日期、大标题占用较多高度 | 压缩顶部，给当前动作与组行更多空间 | 延续浅色橙红，但通过空间分配提升实用性；检查 320 宽度与键盘开启状态。 |
| 训练时中/EN 常驻顶部 | 正式产品考虑放到设置，讨论稿继续保留便于对照 | 语言切换通常低频；入口位置仍需用户确认。 |

Strong 的组内输入、完成勾选与整场 Finish 提供交互参考；Hevy 的完成标记、训练变量调整与整场完成流程可交叉参考。它们证明这些模式已有应用，不证明对 FitQuest 的目标用户一定最优。[Strong 操作说明](https://help.strongapp.io/article/229-my-first-workout)、[Hevy 录组说明](https://www.hevyapp.com/features/track-workouts/)

“上次训练”参考值得排入后续候选，但不同于当前讨论稿的“本场上一组”：它需要查询已保存历史，并定义动作身份、重命名、中英别名与缺失历史的处理。Hevy 也将 PREVIOUS 参考列与本次重量/次数区分，不能把预填值当作已经完成的组。[Hevy 对参考值与计划值的说明](https://help.hevyapp.com/hc/en-us/articles/34105442929943-Previous-Workout-Values-Vs-Routine-Values-How-to-Adjust-in-Settings)

Hevy 的套餐表写有“Data history 3 months”，但另一官方 FAQ 明确历史训练可以持续向前查看；因此不把该措辞解释成“三个月前记录被删除或不可访问”。更细的免费统计范围待实机核对。[历史说明](https://www.hevyapp.com/features/best-way-to-track-workouts/)

我的成本判断：录组、历史和本地统计可主要由端侧承担；动作视频库增加内容制作、版权与维护工作；云同步和手表增加账号、冲突处理与设备测试；AI 推荐还需要评估、支持及可能的服务费用。这是架构与运营工作量判断，未拿到竞品实际成本或净利润数据。

对 FitQuest 的暂定商业方向：保持可用的基础记录和已有数据访问，未来验证模板、深入统计等增强价值；本地工具的买断与持续服务的订阅分别评估。目前不实施付费，也不把下载量、评分或标价当作收入预测。

## 下一步及范围控制

1. 第二轮界面比较增加“行内录组”方案，继续使用用户已接受的浅色橙红和短文案。先得到实际操作反馈，再调整正式页面。
2. 用同一组任务比较两稿：记录三组，其中一组改重量；改错一组；切换动作再返回；切换语言；完成后取消确认。记录时间、误触、返回次数和是否需要解释。先由产品负责人体验，后续按原计划收集五位目标用户证据。
3. 行内编辑若仅改变界面呈现，可以映射现有 FR-005/007/008/009/011/019。待录输入必须与已录有效组分开，预填数据未经确认不得计入已完成组数。
4. 本次未批准新增动作库、跨场历史参考、模板、休息计时、AI、社交或支付。把它们保留为候选，仍先完成现有最小闭环。真实训练数据试用前，按已有隐私任务处理导出与同意要求。
5. 本轮只形成研究与共创记录，不改动应用代码，不将研究结论当作 UI 获批或用户验收通过。

## 本步学习验收

- 必须学会：竞品功能事实、单条用户反馈、产品推断三者的区别；以及体验价值与付费点的关系。
- 目标等级：来源核对 L2，产品取舍 L3。
- 掌握证据：指出一个现在可以比较的界面调整、一个应延期的功能，并解释原因；再用 Fitbod“没找到暂停”的评论与开发者回复说明为什么不能直接把评论当作功能事实。
- 汇报口径：“已对六款代表性产品完成公开资料调研，整理七条反馈线索，提出行内录组等待验证方案；尚未安装实测、确认新界面或证明商业可行性。”
- 未达到目标：重读事实/判断两列及评论原文，删去缺少依据的结论，再完成一次取舍说明。学习掌握待用户实际反馈。
