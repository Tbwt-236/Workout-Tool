# FitQuest 产品决策记录

## D-001：确认初始市场、用户和 MVP 边界

- 日期：2026-08-02
- 状态：Accepted
- 决策者：产品负责人

### 背景

FitQuest 需要在个人开发者资源范围内找到可验证的市场切口，同时避免直接复制成熟训练记录产品。旧 Streamlit 原型包含任务、XP、勋章、排行榜和模拟数据，但不代表移动端 MVP 的必选范围。

### 决策

1. 核心用户定义为中文力量训练新手，大学生作为首批访谈入口。
2. 产品聚焦“帮助用户持续完成真实训练”，以低摩擦记录、可降级训练任务和可解释游戏化反馈形成差异化。
3. MVP 不包含公开社交、饮食系统和自由生成式 AI 训练计划。
4. 允许从同学、朋友、健身房用户和训记用户中招募首批访谈对象。
5. 首发目标市场为中国大陆。

### 影响

- 在进入公开测试前增加 APP/ICP 备案、发布主体、敏感个人信息、应用内支付和隐私政策检查点。
- 访谈需要覆盖现有训练记录方式、计划中断场景、真实训练频率和付费行为。
- `legacy/streamlit/` 的公开排行榜和动态墙不进入首个移动端规格。
- 商业模式继续采用“免费核心记录 + Pro 个性化与洞察”的待验证假设。

### 复查触发条件

- 12 次访谈无法支持“坚持问题”是前三大痛点。
- 中国大陆发布主体或备案路径在当前条件下不可行。
- 可用性测试显示目标用户更需要纯记录工具而非任务与计划降级。

## D-002：用户招募由产品负责人自行管理

- 日期：2026-08-03
- 状态：Accepted
- 决策者：产品负责人

### 背景

第一轮访谈原先提供了 15 个匿名候选编号作为招募辅助。产品负责人已经确认能够自行找到合适人选，不需要开发 Agent 管理或检查候选名单。

### 决策

1. 访谈对象的寻找、联络和排期由产品负责人负责，可以在仓库外管理。
2. 候选名单是否填满不得作为创建和评审功能规格的技术阻塞项。
3. 仓库只在产品负责人提供访谈结果时记录匿名问题证据，不保存姓名、微信、电话或其他直接身份信息。
4. 本决策不取消产品计划中的发现证据门槛；后续 MVP 调整仍应依据真实访谈和可用性测试结果。

### 影响

- `PARTICIPANT_TRACKER.md` 降级为可选工具，不要求维护 15 人名单。
- Agent 可以继续规格定义和低成本发现工作，但不得把未经验证的假设描述为已被用户研究证实。

## D-003：批准首个移动端训练记录闭环规格

## D-009：持续推进 App，先完成无账号原生验证

- 日期：2026-10-02
- 状态：执行中；用户明确纠正为App，并授权持续自动开发、每阶段反思。目前无开发者账号。

保留Expo + React Native及既有001规格，无小程序迁移。先安装任务目录隔离的Android工具链，构建仅本地测试的App，不注册账号或上传商店；iOS完整Xcode仍缺失。Android测试包临时标识`dev.fitquest.local`，不作为正式发行标识；调试签名不作为生产签名。

Android prebuild实测提示缺少`expo-system-ui`，导致app.json已声明的浅色样式不能完整应用到Android系统层。按已批准浅色设计补充SDK57官方模块57.0.4，使用配置插件，不添加网络、账号或数据采集。替代方案是维护手工原生主题配置，会与Expo生成流程重复；跟随同一SDK模块维护成本较低。依据：本地Expo bundledNativeModules.json及[官方SystemUI文档](https://docs.expo.dev/versions/latest/sdk/system-ui/)。这次依赖用于落实已有配置，不扩展产品功能，原生效果须构建后验证。

同日Doctor实际20/21，唯一失败为SDK57补丁版本不匹配；按Expo官方检查建议更新expo57.0.26、constants57.0.20、linking57.0.11、router57.0.24，不跨SDK/React Native大版。维护原因是恢复官方兼容矩阵；不将这些补丁宣称为上游安全告警修复。安装后重新跑完整测试、类型、lint、Doctor、audit与导出，版本以锁文件为准。

每阶段按TDD、实际运行检查、独立审查及中文学习验收推进；新界面与隐私采集仍需具体确认。完整执行记录见docs/handoff/2026-10-02-app-lifecycle.md。

原生生成清单另发现模板/传递依赖默认声明外部存储读写、悬浮窗、振动；001源码无相应用途。使用Expo现有android.blockedPermissions移除这四项，避免给本地训练功能留下多余权限；不新增包或功能。仅设置permissions空数组不能阻止依赖合并。保留INTERNET以支持Metro开发，不将“业务没有网络调用”说成“安装包没有联网能力”；系统备份策略另由002数据流审查，不在此改变。变更须核生成的tools:node移除标记及实际release合并清单/APK；debug开发变体单独检查。
