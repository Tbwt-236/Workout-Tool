## 1. 项目目标

FitQuest 的目标不是复刻一个功能齐全的「训记」，而是先验证一个更窄、可被个人开发者完成并商业化的产品假设：

> 帮助刚开始力量训练、经常因为“不知道今天练什么”或“计划中断”而放弃的中文用户，用低摩擦记录、可降级任务和游戏化反馈持续完成每周训练。

项目同时服务两个结果：

1. 发布一款具备真实用户、留存数据和付费能力的 iOS/Android App。
2. 让产品负责人完整实践 AI 产品经理的发现、定义、交付、度量和迭代流程。

“成功上架”不是最终成功；能够持续解决问题、形成留存并验证付费意愿才是商业成功的前提。

## 2. 初始目标用户与问题

### 核心用户

- 18–30 岁中文用户，力量训练经验约 0–18 个月。
- 有健身目标，但训练频率不稳定。
- 用过备忘录、表格、训记或其他训练 App，但觉得记录复杂、计划难坚持或反馈不够有动力。
- 第一批访谈和内测优先从大学生及身边可触达用户开始，降低获客成本；验证后再决定是否扩大人群。

### 核心工作（JTBD）

当我准备训练但时间、器械或状态发生变化时，我希望立刻知道今天最合适的最低可行训练，并能快速记录和看到进步，从而不因一次中断放弃整周计划。

### 目前需要验证的高风险假设

1. “缺乏坚持”比“缺少动作库”更值得解决。
2. 游戏化反馈能提高真实训练完成率，而不仅是增加打开 App 的次数。
3. 用户愿意为持续更新的个性化计划和进步洞察付费。
4. 用户允许产品在明确授权和最小化收集的前提下使用训练数据生成 AI 建议。

## 3. 竞品判断与差异化

| 产品 | 已经做强的能力 | FitQuest 不应正面复制 |
| --- | --- | --- |
| 训记 | 训练计划、饮食记录、数据可视化、动作指导和低价会员 | 大而全的训练饮食工具 |
| Strong | 快速力量训练记录、进步图表、设备与健康平台集成 | 单纯做更完整的训练日志 |
| Hevy | 训练记录、进步追踪和健身社区 | 在没有用户规模时先做公开社交网络 |
| Fitbod | 自适应/AI 训练推荐和丰富动作库 | 在缺少可靠训练数据时承诺“AI 自动科学训练” |

FitQuest 的初始差异化：

- **坚持优先**：核心指标是完成真实训练，不是签到或浏览时长。
- **计划可降级**：时间不足或器械不可用时，提供 10/20/40 分钟替代任务。
- **记录够快**：从打开 App 到开始第一组训练的目标时间小于 10 秒。
- **反馈可解释**：XP、等级、任务和建议必须能追溯到真实训练行为。
- **AI 是增强层**：基础记录永远可用；AI 负责复盘、调整和解释，不冒充医疗诊断。

## 4. MVP 范围

### 必须具备

1. 新手目标与可用器械选择。
2. 至少一套可解释的入门力量训练模板。
3. 开始训练、记录动作/组数/次数/重量、休息计时、完成训练。
4. 训练历史、个人最佳和基础周趋势。
5. 基于真实训练完成情况的每日任务、XP、等级和连续训练反馈。
6. 本地优先保存，异常退出后可以恢复未完成训练。
7. 隐私说明、数据删除和可导出路径。
8. 基础产品事件统计与崩溃监控，且不把健康数据用于广告画像。

### 明确推迟

- 饮食与卡路里数据库。
- 公开排行榜、动态墙和陌生人社交。
- 教练市场、直播课与电商。
- Apple Health/Health Connect 自动同步。
- 摄像头动作识别和姿态评分。
- 完全由大模型自由生成训练计划。
- 简体中文/英文之外的更多语言和 Web 全功能版。2026-09-13 用户已明确要求简体中文与英文，纳入 001 的 FR-019；两种语言共用同一应用和训练数据。

旧 Streamlit 中的排行榜、动态墙和模拟同步仅作为概念参考，不直接迁移到 MVP。

## 5. 商业模式假设

### 免费层

- 完整的训练记录流程和历史数据。
- 基础训练模板、任务、XP、等级和个人最佳。
- 数据导出与删除。

### Pro 层（留存验证后再开发）

- 根据历史表现调整的训练计划。
- 每周 AI 训练复盘、疲劳/停滞信号解释和下周建议。
- 高级趋势、训练量与动作维度分析。
- 更多计划模板、计划版本与跨设备同步。

### 定价实验

不在 MVP 阶段锁定价格。候选实验为人民币年付 68/98/128 元或等值地区价格，先通过访谈、假门测试和内测付费意愿验证。由于 AI 推理和云服务具有持续成本，不把“永久会员”作为默认长期模式。

不采用广告作为主要收入来源：它与健康数据的信任关系冲突，而且 Apple 对健康与健身数据用于广告和营销有严格限制。

## 6. 北极星指标与阶段门槛

### 北极星指标

**每周每位活跃用户完成并保存的有效训练次数。**

### 支持指标

- 激活：安装后 24 小时内完成第一场训练。
- 首次价值时间：从首次打开到开始第一组训练的时间。
- 留存：D1、D7、D28，以及第 2/4 周仍完成训练的比例。
- 训练质量：训练完成率、计划降级后的完成率、记录中断恢复率。
- 商业：付费意愿、试用开始率、试用转付费率、退款率、MRR。

### 验证门槛（均为初始假设）

| 阶段 | 进入下一阶段前的证据 |
| --- | --- |
| 发现 | 至少 12 次访谈，其中至少 8 位属于目标用户；形成重复出现的前三个问题 |
| 可用原型 | 至少 5 位用户无需指导完成“开始—记录—结束—查看历史” |
| Alpha | 至少 20 位测试者；激活率目标 ≥60%，收集主要流失原因 |
| Beta | 50–100 位测试者；D7 留存目标 ≥30%，第 4 周训练留存目标 ≥20% |
| 付费实验 | 用户明确认可 Pro 价值；先验证购买意图，再投入订阅工程 |

这些数字不是成功保证，而是帮助停止无证据扩张范围的决策门槛。

## 7. 技术方向（尚未成为最终架构决定）

- 客户端：Expo + React Native + TypeScript，目录为 `apps/mobile/`。
- 导航：Expo Router；具体 SDK 版本在脚手架当天依据官方兼容性重新确认并锁定。
- 数据策略：先本地优先，训练会话和游戏化规则保持可单元测试；云同步在本地价值验证后接入。
- 生产开发：早期界面学习可以使用 Expo Go；涉及订阅、推送、健康平台或其他原生能力时切换到 development build。
- 发布：使用 EAS Build/Submit 或经验证的等价流程生成并提交 iOS/Android 构建。
- 订阅：到商业验证阶段再决定 StoreKit/Play Billing 封装方案，不提前添加付费依赖。
- AI：服务端调用、结构化输出、可审计提示词、成本上限和失败降级；不在客户端保存密钥。

## 8. 分阶段交付路线

### 阶段 0：发现与项目治理

- 产品负责人确认本计划中的用户、问题和 MVP 边界。
- 初始化 Git 并保存迁移前检查点。
- 初始化 GitHub Spec Kit 和产品 constitution。
- 完成访谈提纲、12 次用户访谈和竞品任务测试。
- 首发目标市场已确认为中国大陆；公开测试前评估 APP/ICP 备案、主体、敏感信息和支付合规。

退出条件：目标问题得到访谈证据支持，产品负责人批准 MVP 边界。

### 阶段 1：移动端基础与第一条垂直切片

- 初始化 `apps/mobile/`，建立 TypeScript、导航、主题和测试基线。
- 完成最小闭环：创建一场训练 → 记录一组动作 → 完成 → 历史页可见。
- 所有核心业务规则先写失败测试，再实现。

退出条件：真机可运行；自动测试通过；用户能完成最小闭环。

### 阶段 2：可用训练产品

- 动作与模板、组次重量、休息计时、训练恢复。
- 历史、个人最佳、基础趋势。
- 新手引导和空状态。

退出条件：5 位目标用户完成可用性测试，严重阻塞问题清零。

### 阶段 3：FitQuest 差异化

- 10/20/40 分钟计划降级。
- 基于真实训练的任务、XP、等级、连续训练和勋章。
- 验证游戏化是否提高训练完成率。

退出条件：游戏化实验显示正向行为信号，且没有明显诱导无效训练。

### 阶段 4：Alpha/Beta 与可靠性

- 账户、云同步和必要的服务端能力。
- 产品分析、崩溃监控、隐私、导出和删除。
- TestFlight 与 Android 封闭测试。

退出条件：达到 Beta 门槛，关键数据无丢失，隐私清单完成。

### 阶段 5：付费价值与订阅

- 先测试 Pro 价值文案和购买意图。
- 实现每周复盘/计划调整中的一个付费垂直切片。
- 接入 App Store/Google Play 订阅、恢复购买和权益校验。

退出条件：真实用户完成受控付费测试；收入能够覆盖可变服务成本的假设成立。

### 阶段 6：商店发布与增长循环

- 完成商店账号、备案/地区合规、隐私政策、支持入口和订阅说明。
- 准备截图、预览、关键词、审核说明和演示账号。
- 分批发布，监控崩溃、留存、评价和退款。
- 只依据数据和访谈进入下一轮功能规划。

## 9. 上架与合规预算事实（2026-09-23校正）

- Apple Developer Program为US$99/会员年，实际本币金额以注册为准。大陆iOS/iPadOS自2026-03-15起标准IAP/付费App交易25%，符合Small Business等条件的交易12%；海外地区单独核算，不沿用旧统一15%假设。[Apple会员](https://developer.apple.com/support/compare-memberships/)、[大陆费率公告](https://developer.apple.com/news/?id=dadukodv)
- Google Play 开发者注册通常为一次性 25 美元；订阅和服务费规则会因地区、项目和发布时间变化，上架前必须重新核对。
- Apple 要求自动续订订阅持续提供价值；健康与健身数据不得用于广告、营销或无关的数据挖掘。
- 中国《个人信息保护法》将医疗健康和行踪轨迹列为敏感个人信息，处理时需要特定目的、充分必要性、严格保护，并通常需要单独同意。
- 在中国境内提供互联网信息服务的 App 需要评估并办理相应 APP/ICP 备案；首发地区必须在公开测试前确定。

本计划不构成法律或税务意见。正式发布前需要依据主体、地区、数据流和商业模式进行专项核对。
