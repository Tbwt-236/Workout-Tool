## 1. 你在项目中的角色

你不是向 AI 提需求后等待成品的人，而是 FitQuest 的产品负责人。你负责：

- 选择值得解决的问题。
- 判断证据是否足以投入开发。
- 确认规格和验收标准。
- 亲自体验每个版本并记录问题。
- 根据用户行为和访谈决定继续、修改或停止。

Codex 是主开发 Agent，同时承担产品方法教练、技术解释和阶段性审查。Cursor 是统一工作台，不作为第二个自动改代码的 Agent。

## 2. 五个学习阶段

### A. Discover：发现问题

学习概念：目标用户、JTBD、用户访谈、问题强度、现有替代方案、确认偏误。

你的实践：

- 招募 12 位目标用户。
- 观察一次真实训练记录过程。
- 询问过去行为，不询问“你会不会用我的 App”。
- 整理重复问题和原话证据。

输出物：访谈提纲、访谈记录、问题排序、竞品任务对比。

### B. Define：定义产品

学习概念：价值主张、用户故事、MVP、非目标、验收标准、北极星指标。

你的实践：

- 用一句话说明用户、场景、问题和结果。
- 为第一条训练记录闭环写规格。
- 明确哪些想法本阶段不做。

输出物：产品 constitution、Feature Spec、验收条件、事件统计方案。

### C. Decide：做出取舍

学习概念：风险优先、机会成本、RICE/影响-成本判断、可逆与不可逆决策、实验设计。

你的实践：

- 每次新增功能前说明证据和预期指标。
- 对高风险假设先做最低成本实验。
- 维护决策记录，写清“为什么现在做”。

输出物：决策记录、实验卡、优先级列表。

### D. Deliver：与 AI 交付

学习概念：规格驱动开发、垂直切片、TDD、数据流、状态管理、验收和回归。

移动端技术栈的入门顺序、FitQuest 数据流、官方资料和掌握练习见
[`MOBILE_TECH_STACK_FOUNDATIONS.md`](MOBILE_TECH_STACK_FOUNDATIONS.md)。

每个完成的任务中，Codex 都必须用中文提供学习验收；实现任务还必须说明：

1. 正在解决什么问题。
2. 你需要掌握哪些概念。
3. 哪些文件和数据流最重要。
4. 如何运行和验证。
5. 哪些内容有意推迟。

你的实践：在手机上按验收条件操作，不以“Agent 说完成了”作为完成证据。

输出物：测试、实现、验证记录、代码审查、版本说明。

### E. Measure：度量与迭代

学习概念：激活、留存、漏斗、同期群、定性与定量证据、虚荣指标、单位经济模型。

你的实践：

- 每周查看用户完成训练的实际次数。
- 访谈流失用户，而不只询问活跃用户。
- 将每次迭代与一个主要指标绑定。
- 记录预测与结果的差距。

输出物：周度产品复盘、指标看板、实验结论、下一步建议。

## 3. 单一 Agent 工作协议

每项功能按以下顺序推进：

1. 你描述用户问题或观察到的证据。
2. Codex 将问题整理为规格草案，不立即编码。
3. 你确认目标、非目标和验收条件。
4. Codex 使用测试驱动开发实现一个小的垂直切片。
5. Codex 提供新鲜的测试与运行证据。
6. Codex 进入独立审查步骤，检查规格、测试、架构和风险。
7. 你在真机完成产品验收并记录学习。

同一时间只允许一个写入任务。遇到重大里程碑、长期故障或上架前审计时，才临时引入第二个只读审查者。

## 4. 掌握程度与每步学习验收

所有任务统一使用以下等级，避免“了解一下”这类无法验证的表述：

| 等级 | 含义 | 你能够做到的事 |
| --- | --- | --- |
| L1 能复述 | 理解用途 | 用自己的话解释概念、用途和一个 FitQuest 例子 |
| L2 能照做 | 能按步骤操作 | 按清单完成操作、找到重要文件并读懂正常验证结果 |
| L3 能独立应用 | 能独立验收和判断 | 不依赖逐步提示完成任务，解释取舍与数据流，并定位常见问题 |
| L4 能教学与决策 | 能向别人讲清并做取舍 | 比较方案、用证据维护选择，并说明何时需要重新决策 |

每次任务结束必须提供：

```text
本步学习验收
必须学会：
目标等级：
掌握证据：
汇报口径：
未掌握时的处理：
```

最低要求：产品问题、用户、范围、非目标、成功指标和重大取舍在里程碑验收前达到 L3；数据流、状态生命周期、测试策略、隐私边界和验证命令在每个实现切片达到 L2，并在最终汇报前达到 L3。
